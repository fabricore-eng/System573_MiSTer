# PLAN — gate 4: k573dio DIO-board RAM (MEMORY CHECK 22G/22H/22J), DDR3-backed (2026-07-02)

Follows `docs/2026-07-02-ddrsbm-erase-strap-result.md` (gates 2+3 cleared; install
MAME-golden-exact). Memory: `[[fabricore-573-digital-bringup]]`. Ground truth below was
gathered by a 3-lane observe workflow this session (MAME oracle + full-EXE disasm + RTL
audit, all high-confidence) — the next session can start at the DESIGN, not archaeology.

## 1. THE GATE, FULLY DIAGNOSED

ddrsbm's post-install POST streams a test pattern through the DIO RAM port and fails:
`MEMORY CHECK  22H BAD / 22J BAD / 22G BAD`, then halts forever (0x8009a578 spin).

**Root cause is PURELY BACKING SIZE — the register model is already correct.**
`rtl/k573dio.v` implements the full MAME-faithful RAM port (b0/b2 write-addr latch,
b4 data R/W with independent auto-inc read/write pointers, b6/b8 read-addr latch,
25-bit addresses) but backs it with `RAM_WORDS=4096` = **8 KB** (the sim-sized array,
k573dio.v:89, not overridden at the system573_top.v:288 instantiation). The check
sweeps 24 MB; everything aliases mod 8 KB; all three chips read back garbage → BAD.

## 2. GROUND TRUTH (verified, cite-checked)

**MAME oracle (k573dio.cpp/k573fpga.cpp, mame0285):**
- RAM = ONE flat share, `0x2000000` bytes = **32 MiB as 16M x 16 LE**, every address
  masked `0x1ffffff`. Physical board = **3x HY51V65164A 8 MiB EDO DRAM = 24 MiB**;
  MAME rounds up to a power of two. Unwritten RAM reads 0x0000.
- Registers (byte offsets from 0x1f640000, all 16-bit): `b0`/`b2` = write-addr
  hi/lo (latch, write-only), `b4` R = `ram[read_adr>>1]` then `read_adr += 2`,
  `b4` W = `ram[adr>>1] = data` then `adr += 2`, `b6`/`b8` = read-addr hi/lo.
  Two INDEPENDENT auto-inc counters (code truth; a comment claims shared — follow
  the code). Reset: both counters 0.
- MP3 coupling: k573fpga streams from the SAME share (start/end regs a0-a6,
  key a8, fpga_ctrl ae bits 13/14; per word: read `ram[cur>>1]`, decrypt
  (ddrsbm scheme keyed by crypto_key1 only), byte-swap, high-byte-first to the
  MAS3507D; `fpga_ctrl_r` = 0x1000 while streaming). ddrsbm sets
  `set_ddrsbm_fpga(true)`.
- POST also requires `fpga_status` 0xf6 == 0xb000 — **our read mux already
  returns it** (k573dio.v:179).

**Game disasm (ddrsbm EXE; scripts in local/tracedig/memcheck_*.py):**
- Sequencer 0x8009a2a4, per-chip test 0x80099fd4. Chip map (base table 0x800d9000):
  **22H = 0x000000, 22J = 0x800000, 22G = 0x1000000 — 8 MB each, 24 MB total.**
- Per chip x 2 phases: set write ptr ONCE, stream-write the FULL 8 MB
  (back-to-back `sh -> 0xb4` in 0x200-halfword bursts, watchdog kick + vsync
  pacing between bursts), set read ptr, stream-read + compare the full 8 MB.
  Pattern = free-running 16-bit counter (phase 0 incrementing with wrap that
  skips 0xffff; phase 1 decrementing skipping 0). ONE mismatch anywhere = BAD.
  No status reg is polled. The auto-increment must be exact across 0x400000
  sequential accesses per region.
- MEMORY CHECK is the LAST POST item: all-OK returns straight into the game
  main loop (attract). **Clearing gate 4 = ddrsbm RUNS** (MP3 audio still absent
  — that's P4 proper, the gate after).

**RTL audit:**
- k573dio.v register decode complete (see §1); mp3stream reads the same array
  through a COMBINATIONAL port (`s_rd_data = ram[...]`, k573dio.v:97) — a real
  external backing must break that zero-latency assumption (mp3stream FSM
  already has S_ADDR/S_STB/S_CAP states; insert a wait/handshake).
- **BRAM cannot hold it**: free ≈ 3.45 Mbit ≈ 422 KB vs 24-32 MB needed.
- **Main SDRAM cannot hold it** (32 MB module fully committed: PSX RAM 0-4MB,
  BIOS @0x800000, 16 MB flash @0x1000000-0x1ffffff; free holes ≈ 11.5 MB
  non-contiguous). A 64 MB-module requirement would change user HW for all
  digital games — fallback only.
- **DDR3 (f2sdram) is the home**: 29-bit x 64-bit DDRAM port, vast headroom
  (PSX uses it for 2 MB VRAM @0x30000000 + savestates). Needs a small arbiter
  between the psx DDRAM master (emu.sv:1348-1357) and a new DIO client.
- Found in passing: system573_top.v:288 instantiates k573dio with **DDRSBM
  param left 1'b0** — wrong MP3 descramble scheme for ddrsbm; fix in the same
  change (plumb from a game-select or tie per-.mgl via CONF_STR later; note
  only, decide at implementation).

## 3. DESIGN (proposed)

DDR3-backed 32 MiB DIO RAM (mask 0x1ffffff like MAME; 24 MB is what the check
touches), window in an unused DDRAM region (away from FB_BASE 0x30000000 +
savestate areas — pick and DOCUMENT the base in PLATFORM.md):

1. `k573dio.v`: add `BACKING_EXTERNAL` mode (s573_flash precedent). Ports:
   posted-WRITE stream (data+addr FIFO out) and a READ req/ready. Keep the 8 KB
   internal array for standalone sim under the parameter.
2. CPU read path (`lhu 0xb4`): stall via the EXISTING exp1 wait (patch 0006
   holds READS; `flash_wait` precedent through system573_top). Sequential reads
   ⇒ add a small prefetch line (auto-inc makes next-address known) so the 8 MB
   sweep isn't one round-trip per halfword.
3. CPU write path (`sh 0xb4`): EXP1 writes NEVER stall ⇒ posted-write FIFO
   (BRAM, generous depth; the game paces 0x200-halfword bursts with vsync gaps).
   Overflow = fail LOUD in sim ([[no-mask-fault-with-fake-data]]).
4. mp3stream port: convert to the same req/ready (insert a wait state in its
   FSM); coherent with CPU writes through the shared backing.
5. emu.sv: DDRAM arbiter (lean — ALM is at 91%): psx master > DIO client;
   single-beat or short-burst 64-bit ops; the 16-bit words pack 4-per-beat
   (read-modify-write for sub-beat writes, or byte-enables if the avalon port
   carries them — check ddram byteenable width first).
6. RED/GREEN: new `k573dio_ram` target; TB drives the MAME memcheck shape
   (counter pattern across widely-spaced addresses in all three 8 MB regions +
   the 8 KB alias boundary 0x2000), behavioral DDR3 responder like
   tb_s573_flash_sdram's models; RED define `DIO_RAM_STUB` = today's aliasing
   array. Extend the streaming test against the handshake port.

## 4. RISKS / GUARDRAILS

- **f2sdram bridge placement is MARGINAL** ([[f2sdram-bridge-placement-marginal]]):
  the DIO client rides the same bridge; any wedge after this build is FIRST a
  bridge-re-roll suspect (warm reboot + uptime<60s + ONE load_core discipline).
- ALM 91%: keep the arbiter/FIFOs lean; watch the fit report.
- DDR3 bandwidth: memcheck streams ~96 MB total through single 16-bit accesses —
  bounded by EXP1 bus pace (~10-20 clk1x/access), trivial for DDR3; the risk is
  LATENCY on reads (hence the prefetch), not bandwidth.
- Don't touch: mas3507d_i2c.v, atapi.v, the flash/erase path (all silicon-proven).
